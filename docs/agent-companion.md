# 单会话角色

本地会话的“＋”菜单提供独立创建入口。创建时选择未用于聊天的新角色，一个角色固定一个主窗口。普通角色、普通 Agent、群聊和旧版长期会话沿用原路径，已有聊天不会自动转换。

## 独立记忆与迁入

单会话角色使用当前窗口的独立长期记忆，分类为用户画像、角色画像、双方关系、经历档案、约定、未解决事项。经历按原话参与者记录，允许独自经历。上游原有的记忆版本、来源回查和 Embeddings 接口被适配到独立存储；这些基础能力并非本功能首次提供。

核心记忆每次提供给角色，但占用输入容量；人工选择和锁定保护持久保存。管理页可搜索、分类、编辑、查看修改记录和逐条定位原话。全局 Agent 记忆不参与此模式的事实整理。

已有会话可先创建本机快照，再通过内置模型按公开转换规则重建记忆并迁入独立副本。来源编号、有效期、旧记忆可信度和原话变化均需校验；不合格批次保留进度，最多有限补正。未完成结果不提前发布，原会话和原资料保留。支持中断恢复及删除转换记录，删除前显示影响范围。

数据导出中心可往返保存模式、归属、记忆、来源、整理进度及关系资料。单独聊天 JSON 不承载完整独立记忆，不能代替完整归档。迁入作业和请求缓存不作为可重放资料导入；恢复仅影响本次导入的角色。

## 整理、回查与模型

后台整理在完整回复保存后触发，模型只处理目标旧段；近期原话和已有记忆是辅助参考，不提前重复入库。原话容量不足、来源变化或结果格式错误时不推进进度。核心与锁定条目优先保留，放不下的原话仍留在原处。

近期窗口、目标段及参考记忆均受实际模型上下文限制。核心维护目标约 1000 估算 Token；旧超额核心保留并提示，整体放不下时停止发送。预算是应用的估算限制，不能当作服务商精确计费或缓存命中保证。

独立记忆和经历采用关键词与缓存向量混合检索，向量失败回退关键词。同一资料库的单会话角色共用向量开关和模型，默认关闭，添加模型不自动开启。主动回查按本条回复累计额度，默认最多 3 轮、约 4000 Token、单次最多 1500 Token，并受可用上下文限制；额度用尽后由角色继续回答。自动提供的记忆仍占输入容量。

角色可配置独立聊天模型主备队列；未配置时沿用上游默认。显式队列损坏或全部失效会报错，不静默扩大到其他模型。新模式不使用滚动历史总摘要或手动压缩，普通模式保留上游行为。

## 关系与内心想法

上游已具有六维关系和角色状态。单会话角色扩展独立模型的情绪、长期关系文字评估及来源记录，默认关闭，由用户选择模型并决定是否补评旧历史。成功回复落库后检查全部待评对话，评估失败保留已有状态；超时可恢复，不伪造旧历史依据。

角色视角思考和内心想法标记为 **Beta（测试版）**。思考提示、自定义偏好和正文标签解析是在上游原生 reasoning/thinking 通道基础上的扩展。原生通道、工具续接和签名继续保留，普通历史不重复回传旧思考。正文最开头第一段半角或全角圆括号可实时归入内心想法，后续括号保留；关闭角色视角思考时不转换。

显示思考与角色视角思考共同控制内心想法展示，正文独白另有本会话显示偏好。解析和文字标注本身不增加模型调用；后台整理、转换、向量检索和关系评估可能产生所选服务商的费用。模型是否遵循格式及服务端是否流式返回仍需对应服务商验证。

## 数据库与验证

保留官方已发布的 1→52 迁移和 schema 原样，追加 **52→53**。新迁移创建完整独立记忆、归属、迁入、关系表及角色队列、会话标题字段，不复用个人版同号迁移，不忽略 Room 校验或清库。个人版旧数据库不是这条官方升级链的输入。

运行 `:app:compileDebugKotlin` 和 `:app:testDebugUnitTest`；随后以 Python 3 运行 `scripts/check_companion_migrations.py`，在隔离 SQLite 中执行单测导出的真实迁移 SQL，比较官方 48—52 升级后与新建 53 的结构、数据和归属约束。

`UpstreamCompanionMigrationAndroidTest` 提供官方 48—52 到 53 的 Room 设备回归；迁入、归档、合成检索和进程恢复测试保留。回环 TLS 证书由 JDK keytool 在测试构建目录生成，不提交二进制证书。JVM 与 SQL 验证不能代替 Android/Room 设备执行、真机界面或真实模型质量验收。
